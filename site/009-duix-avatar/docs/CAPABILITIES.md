| 能力 | 输入 | 实际处理与输出 | 证据等级 |
| --- | --- | --- | --- |
| 创建人物素材 | 有人物说话的视频、名称 | 转成 H.264，提取音频，处理参考声音，保存人物及声音关联 | 客户端代码确认 |

## 两种典型操作

### 文案到视频

1. 导入本人或已获授权的人物视频，建立素材记录。
2. 输入要讲的新稿件，选择人物和声音。
3. 生成配音，再以人物视频和配音提交合成。
4. 等待任务完成，查看并导出成品。

适合经常修改稿件的项目介绍与知识讲解。配音读错词时，需要调整文本或改用已有音频；项目不会自动核查内容事实。

### 已有配音到视频

1. 准备人物视频和已审核的目标音频。
2. 将目标音频提交给视频服务，生成对应口播。
3. 检查口型、衔接和画面稳定性。

客户端的生成路径支持使用上传音频。Lite Compose 只启动视频服务，因此它适合探索“已有音频＋视频接口”的路径；原客户端新增人物仍会调用声音服务，不能据此承诺 Lite 下全部界面功能可用。

## 不能从这些能力推导出的承诺

| 容易误解的说法 | 准确边界 |
| --- | --- |
| “拥有一个能思考的数字分身” | 已确认的是素材与音视频合成链路，未发现这里集成了知识库问答、决策或自动写稿链路 |
| “直接做实时视频客服” | 仓库定位为非实时合成；异步任务轮询不等于实时音视频对话 |
| “输入照片就能完成所有流程” | 本次核查的创建人物流程接收视频并提取其声音，没有验证照片输入 |
| “能随文案自由表演和换场景” | 尚无证据支持任意全身动作、换装、镜头控制或新场景生成 |
| “10 秒素材必然高度逼真” | 约 10 秒是官方介绍，不代表任何素材都能达到同等质量 |
| “支持多人物等于支持任意底层模型插件” | 素材记录管理与神经网络模型热插拔是不同能力；后者未验证 |
| “批量生成等于高并发服务” | 客户端有等待队列；需要另外测量吞吐、资源占用和失败恢复 |
| “开源就能完整复现模型训练” | 当前树中未发现核心 Python 后端与常见权重文件；容器内容未检查 |

## 质量应当怎么理解

声音相似度、嘴型同步、牙齿与嘴部细节、转头时稳定性、长段落重复感、多语言发音均需通过样片判断。当前没有本机实测数据，因此不提供生成速度、最低显存、最大时长、分辨率上限或相似度百分比。
