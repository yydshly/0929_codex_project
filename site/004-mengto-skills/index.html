01 / WHAT IT DOES

一套视觉设计与前端制作方法库。

MengTo/Skills 把设计规范、页面组织、交互做法和制作经验写成 AI 可以按需读取的技能。它的核心价值，是帮助你把“想做出这样的体验”转成具体的页面结构、视觉规则、代码实现和验收要求。

输入

一个目标或参考

产品说明、研究内容、参考网页、录屏，或想实现的视觉和交互效果。

方法

选择对应的技能规范

明确布局、素材、状态、动效和验证要求；有的技能还附带演示、脚本或代码资源。

产出

可展示、可交互的成果

完整介绍页、不同风格的界面、三维体验、游戏原型，以及审查和交付记录。

并不只是“换风格”。 风格是其中一类；整页叙事、交互实现、三维与游戏系统、参考拆解和交付流程，也各有对应技能。成果由 AI 结合项目与工具实现，技能本身是指导方法。

整页与产品表达 / 8 项

把产品讲清楚

规定字体、配色、留白、网格和材质。适合已有内容需要改版，或一个项目要尝试多个视觉方向。

05 / WHEN YOU WILL USE IT

对你：从研究展示，走向可复用的制作能力。

你目前在做开源项目研究，最直接的用法是把文字研究变成容易看懂、可以体验的网页。之后再按任务扩展到产品与交互原型。

现在

为一个开源项目做能力展示页

整理真实结论 → 选择整页结构 → 确定风格 → 展示实景与证据。产出可分享的研究页，就像当前项目。

可选：landing-page / book-serif-index / workflow-progress-screenshots
价值：让研究成果被看懂、被复用。
有参考时

看到喜欢的网站或录屏，想知道怎么做

拆解版式、素材、滚动顺序与状态变化，再形成具体实现要求；保留来源，避免把参考品牌与数据照搬进自己的项目。

可选：video-to-superprompt / html-to-interaction-prompts
价值：把“这种感觉”变成明确需求。
做产品时

为个人工具或企业 AI 产品制作官网

讲清使用流程、产品证据、边界与演示入口。使用真实产品资料；后台业务、模型接入和权限系统另行开发。

可选：product-proof-saas / operational-enterprise-ai / pricing-page
价值：提高产品表达与沟通质量。
探索体验时

尝试交互展品、三维导览或小游戏

先做一个小而完整的可用原型：一个空间、一段交互或一次战斗循环，再检查手机表现与运行成本。

可选：3d-virtual-tour / build-isometric-arpg / test-playable-web-games
价值：更快把想法变成可判断的体验。
长期积累

把做成功的实现，沉淀为自己的方法

审查实际结果，记录关键参数、限制和踩坑经验，再将可复用的做法提炼成技能与交付流程。

可选：web-technique-to-skill / iterate-until-verified / workflow-ship-change
价值：减少重复摸索，积累个人制作体系。

优先从你正在做的研究展示页和个人工具介绍页开始。三维和游戏能力在任务确实需要空间感或玩法时再采用；收益要以真实成品与验收结果判断。

06 / SCOPE & COMPOSITION

“能做介绍页”与“能开发产品”，范围不同。

operational-enterprise-ai 同时指导页面叙事、视觉、展开行、案例、表单和验收，覆盖范围比单一风格技能更广。它能指导企业 AI 产品的介绍与获客页面，不能据此推断完整 AI 系统已经实现。

该技能指导的成果

说明系统边界、审批、审计与回退；组织解决方案、安全证据、案例和 FAQ；实现页面交互、表单状态与演示入口。

真实产品仍需开发

数据库、模型调用、知识库、认证授权、审批执行、审计存储、后端服务和业务逻辑。页面里的能力承诺必须有真实实现支撑。

组合方式

整页指导确定结构 → 选择一个主视觉规范 → 按需添加局部交互 → 补充素材 → 审查验证 → 交付。

技能之间可以有职责重叠。以任务为准选定主规范，发生冲突时明确取舍；不必把多个风格叠加使用。

研究依据：固定版本 798db0a；全量元数据与目录核对，原有正文抽查，并补充读取六个演示风格与企业 AI 页的规范。能力描述与个人使用建议属于研究归纳；实际构造与验证范围单独标明。
