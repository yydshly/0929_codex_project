# 子项目收录规范

## 编号与目录

- 从 `001` 开始，取历史最大编号加一；不要按当前目录数量分配编号。
- 名称采用小写英文和连字符，例如 `001-project-name`。
- 编号是稳定标识，项目改名或归档时保留编号。超过 `999` 后继续使用 `1000`，索引按数字排序。
- 同一项目的持续研究放在原目录；研究不同上游项目时新建编号。
- 原仓库通过链接引用。确需引入源码时，在子项目中记录版本与许可证；不要直接复制嵌套的 `.git` 目录。

## 创建第一个子项目

在仓库根目录的 PowerShell 中执行以下示例，将 `project-name` 替换为实际名称。后续新增项目时同步替换编号。

```powershell
$projectPath = 'projects/001-project-name'
if (Test-Path -LiteralPath $projectPath) { throw '目标目录已存在，请检查编号' }
Copy-Item -LiteralPath 'templates/project' -Destination $projectPath -Recurse
```

1. 填写子项目 `README.md` 中的名称、编号、原仓库地址、研究版本与收录日期。
2. 在 `RESEARCH.md` 中记录问题、运行环境、步骤、结果和结论；未验证的内容明确标记。
3. 将实际截图放进 `assets/`，在子项目 README 中添加图片和说明。
4. 在总 README 的索引中按数字升序添加一行，源库使用 `作者/仓库名` 作为链接文字；首次收录时删除“暂无研究项目”行。
5. 图览和目录 README 同样按编号排序；每个项目只出现一次。有代表图片时再添加图览。没有 Web 演示时填写 `—`，开发中但未上线时填写 `未发布`。

索引行示例（创建对应目录后再使用）：

```markdown
| 编号 | 源库 | 中文研究 | 能力与用途 | 研究进度 | 在线展示 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 001 | [owner/repository](https://github.com/owner/repository) | [项目名称](projects/001-project-name/README.md) | 一句话概括能力与用途 | 研究中 | — |
```

图览示例（添加真实图片后再使用）：

```markdown
### 001 · 项目名称

[查看研究](projects/001-project-name/README.md) · 一句话说明项目价值。

![项目名称：核心功能界面](projects/001-project-name/assets/cover.webp)

图示：说明截图中的功能、场景或本次研究的发现。
```

## 文档与图片

总 README 只保留摘要、索引和精选图片；环境搭建、源码分析、排错及验证细节进入子项目文档。链接使用相对路径，以便在 GitHub 和本地阅读。

图片优先使用 WebP 或 PNG，按内容命名，如 `cover.webp`、`workflow.png`。为图片提供简洁替代文字和说明；引用上游图片时标明来源。避免提交含凭据、隐私或无关桌面内容的截图。

## Markdown 格式

- 标题、段落、列表、表格与代码块之间保留空行；标题级别连续。
- 表格每行的列数与表头一致，单元格内的竖线写作 `\|`。
- 内部文档和图片使用相对链接；源库链接使用可辨认的作者/仓库名，避免含糊的“点击这里”。
- GitHub 固定版本的目录使用 `/tree/<提交>`，文件使用 `/blob/<提交>/<路径>`。
- 发布后修正“未发布”等旧说明；研究是否完成与上游是否实测分别记录。
- README 由构建脚本生成时，应同时修改模板，避免下次构建覆盖修复。

## 完成与归档

`已完成` 表示本次设定的研究问题已有结论，并记录验证环境与上游版本，不表示长期兼容所有版本。归档时保留目录、编号和研究结论，并将索引状态改为 `已归档`。
