# OJO Design Skills · 场景与验收建议

> 场景为研究者整理，不是上游运行实测。模块名称指参考资料，不代表另装多个 Skill。

## 01 · 门店运营与 SaaS 后台

**需求：** 店长要快速发现缺货、筛选门店、完成补货。

**路线：** Convention

**涉及模块：** 设计流程总控 → 设计参数体系 → 组件与八种交互状态 → 设计审查与交付检查

**交付物：** 信息层级、数据与异常颜色、表单状态、导航和审查报告。

**建议验收：** 检查缺货是否容易找到、错误是否能恢复、键盘是否能完成主要操作。

**示例请求：** 为多门店补货后台定义清晰、紧凑的设计系统，保留既有业务流程，补齐表单和异步状态。

## 02 · 品牌电商与订阅服务

**需求：** 用产地、商品和服务特点建立品牌辨识度，同时帮助用户选购。

**路线：** Innovation

**涉及模块：** 设计流程总控 → 材质隐喻与品牌表达 → 首屏与品牌构图 → 设计参数体系

**交付物：** 品牌视觉方向、商品素材要求、首屏构图和订阅入口规范。

**建议验收：** 检查商品内容是否真实相关，购买行动是否明确，移动端是否易读。

**示例请求：** 为强调产地溯源和烘焙日期的咖啡订阅服务建立视觉方向，说明图片、字体、首屏和订阅按钮如何服务用户选择。

## 03 · 个人工具与阅读应用

**需求：** 用户进入页面就要记录、阅读或查找，不想先看宣传。

**路线：** Convention / 视品牌需求调整

**涉及模块：** 设计流程总控 → 首屏与品牌构图 → 组件与八种交互状态 → 图标一致性

**交付物：** 工作区布局、列表与详情关系、编辑状态和统一导航图标。

**建议验收：** 检查核心任务能否直接开始，导航是否与真实信息层级一致。

**示例请求：** 为读书笔记工具规划一个直接进入工作区的首页，定义编辑、保存、空状态和导航图标。

## 04 · 创意品牌与活动页面

**需求：** 传递具体的音乐、文化或创作气质，而不是统一套“高级简约”。

**路线：** Innovation

**涉及模块：** 材质隐喻与品牌表达 → 首屏与品牌构图 → 动效与行为规范 → 反模式与质量约束

**交付物：** 材质/情境说明、编辑式首屏、动效目的与静态替代方案。

**建议验收：** 检查风格是否匹配活动内容，信息能否读清，减少动态效果后内容是否完整。

**示例请求：** 为地下现场音乐活动构建设计方向，保留强烈、粗粝的表达，同时保证时间、地点与购票入口清晰。

## 05 · 现有 AI 页面改版

**需求：** 页面内容空泛、风格混搭、按钮反馈不完整，需要定向修复。

**路线：** General Skill Mode

**涉及模块：** 反模式与质量约束 → 设计参数体系 → 组件与八种交互状态 → 设计审查与交付检查

**交付物：** 问题清单、应保留的部分、定向修复规格和复核计划。

**建议验收：** 逐条检查问题是否解决；不要把更换配色当作任务成功。

**示例请求：** 点评现有会员中心并直接给出一个改进方向，不必再列三套方案；优先处理真实内容、信息层级和交互状态。

## 06 · 团队规范与开发交接

**需求：** 多个页面和开发者需要共享规则，而非每次重新定义组件。

**路线：** 两条路线均可

**涉及模块：** 设计参数体系 → 组件与八种交互状态 → 图标一致性 → 组件与工具库选型 → 设计审查与交付检查

**交付物：** 参数表、组件状态规范、图标规则、依赖选型依据与交付检查表。

**建议验收：** 检查同类角色是否复用同一参数，组件状态是否可实现，库是否兼容项目。

**示例请求：** 把已确认的视觉方案整理为开发交接规范，优先复用现有组件库，并标注缺失状态和仍待验证的事项。
