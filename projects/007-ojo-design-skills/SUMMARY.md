# OJO Design Skills · 能力摘要与个人使用建议

OJO 是面向产品界面设计的 AI 技能包：一个核心 Skill 组织九份参考资料，把初步需求转成页面方向、视觉参数、组件状态、动效规范和审查建议。适合研究展示页、个人工具与后台、品牌官网及现有页面改版；配合宿主编码与测试能力，可进一步落地为可运行的前端页面。

## 先记住四点

### 这个库的能力

从产品任务和受众出发，选择效率或品牌路线，组织视觉、组件、动效、素材与审查工作。

### 可以实现的效果

形成有依据的页面方向、统一的视觉参数、完整的组件反馈和可执行的修复清单；配合编码工具落地界面。

### 适合服务的方向

工具与 SaaS 后台强调清晰和任务效率；品牌、电商与创意页面强调辨识度和体验表达。

### 对你的意义

把“帮我做得好看”变成可讨论、可交接、可复用的规则，服务现在的研究展示和以后的工具开发。

## 全部能力与效果速查

| Skill / 参考模块 | 能力 | 可交付产物 | 使用场景 |
| --- | --- | --- | --- |
| 设计流程总控 · `app-ui-ux-best-practices` | 从产品需求出发，选择设计路线，把视觉方向逐步落实为可供开发使用的规范。 | 视觉方向、设计原则、颜色与排版、间距、组件状态、动效参数、素材要求和建议使用的库。 | 从零开始设计后台、工具或消费应用 |
| 反模式与质量约束 · `anti-patterns.md` | 提醒 AI 避免未经思考的配色、布局、文案和素材套路，并检查实现中容易出错的地方。 | 反模式清单、具体替换建议、可观察的风格参数，以及需要保留的合理例外。 | AI 生成页面有明显模板感 |
| 材质隐喻与品牌表达 · `material-metaphor.md` | 把品牌感受映射到材质和环境，进一步推导表面、光线、边缘、层次与运动。 | 材质与环境说明、光照和深度规则、边缘与纹理策略、组件和动效转译依据。 | 品牌电商、生活方式、日记或创意应用 |
| 设计参数体系 · `visual-tokens.md` | 定义应有哪些颜色、字体、间距与阴影变量，让各页面能使用同一套视觉基础。 | 带用途的设计参数表、色值与使用规则、排版和间距体系；部分上下文约定输出 theme.json。 | 多个页面颜色和圆角各不相同 |
| 组件与八种交互状态 · `component-recipe.md` | 把设计意图翻译为组件样式和状态规则，避免页面只有静态外观。 | 按组件整理的状态规格、Tailwind 类组合、可访问性和响应式要求。 | 表单只做了正常状态，异常状态没有设计 |
| 动效与行为规范 · `motion-system.md` | 先说明为什么需要动画，再确定运动参数、性能要求和减少动态效果时的替代方案。 | 动效目的与触发条件、属性和参数、静态替代方案、性能检查项。 | 按钮点击没有反馈，弹窗出现突兀 |
| 图标一致性 · `icon-guidelines.md` | 统一图标的来源、形态、线宽、尺寸和状态颜色，避免界面像不同素材的拼接。 | 统一库与风格选择、尺寸/线宽/颜色规则、替换清单。 | 导航栏混用了描边、填充和 emoji |
| 首屏与品牌构图 · `hero-enrichment.md` | 先判断是否需要展示型首屏，再选择文字、图片、编辑式构图或动态内容。 | 首屏档位及理由、构图、主行动和素材规格；上下文中约定写入 theme.hero。 | 营销落地页、品牌电商首页、编辑内容入口 |
| 组件与工具库选型 · `component-libraries.md` | 按用途整理界面、动效、图标和专项组件库，帮助寻找符合项目需求的实现基础。 | 候选库及适用理由、可复用能力与需要自行实现的部分。 | 确定设计后，不知道用哪套组件实现 |
| 设计审查与交付检查 · `design-audit.md` | 按清单查找设计与交互问题，说明严重程度、影响位置和修复方向。 | 带位置和严重程度的问题报告、修复建议、正面发现与交付判断。 | AI 页面交付前需要检查 |

只有第一项是独立 Skill；其余九项是参考资料。完整预期效果与边界见 [逐项分析](CAPABILITIES.md)。

## 对你：什么时候用、为什么用

### 现在 · 开源研究展示

**触发时机：** 资料已整理，但页面重点不清、章节样式不统一。

**怎么用：** 用效率路线确定阅读顺序，用视觉参数统一标题、卡片、颜色与间距，用首屏模块说明项目用途。

**预期产物：** 一套研究页规范：核心结论 → 能力与效果 → 场景 → 依据；方便后续编号项目复用。

**如何判断价值：** 读者能找到“是什么、何时用、能得到什么”，手机上也能读清楚。

### 以后 · 个人工具与业务后台

**触发时机：** 要做收藏管理、任务工具，或有初步业务流程的补货后台。

**怎么用：** 先提供用户和核心操作，再细化导航、列表、筛选、表单与反馈；由开发工具实现。

**预期产物：** 页面结构、组件与状态规范，让加载、空白、错误和成功状态都有设计依据。

**如何判断价值：** 关键任务能完成；业务规则、权限、数据接口仍由产品与工程工作补齐。

### 需要对外介绍时 · 产品与项目官网

**触发时机：** 功能可以说明白，希望首屏更有辨识度、能体现产品气质。

**怎么用：** 根据受众选择效率或品牌路线，推导视觉方向、字体色彩、真实素材和行动入口。

**预期产物：** 有明确主题的首屏与品牌规则，帮助访客理解价值和下一步操作。

**如何判断价值：** 内容真实、行动明确、移动端可用；转化提升需要另行验证。

### 已有页面时 · 改版与交付检查

**触发时机：** AI 生成的页面有模板感、图标混搭、反馈缺失，或修改后越来越不一致。

**怎么用：** 提交截图和代码，要求逐处指出问题、说明理由与优先级，再修复和运行验证。

**预期产物：** 可执行的问题清单与调整后的设计规范，减少只凭“感觉不好看”反复修改。

**如何判断价值：** 问题有位置与修复依据；键盘操作、手机布局和真实交互经过检查。

### 长期 · 形成自己的设计方法

**触发时机：** 研究项目和工具越来越多，希望保留成功经验并稳定复用。

**怎么用：** 把确认过的参数、组件状态、参考选择与检查项保存到项目；结合自己的约束修订规则。

**预期产物：** 个人设计基线与交接模板，让后续页面继承已有决定，减少重新解释。

**如何判断价值：** 观察跨页面一致性、重复决策与返工是否减少；不必每次启用全部参考模块。

## 如何开始

保留完整 Skill 目录与 references → 提供用户、任务、页面和约束 → 点名 app-ui-ux-best-practices → 确定方向 → 形成规范或交由宿主实现 → 审查并实际验证。
