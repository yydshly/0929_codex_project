# 能力定位、适用范围与选用指南

**定位：这是面向 Web 产品界面的设计、优化、审查与探索技能集合。** 当前固定版本包含 11 个 skill，核心是界面质量；这里的界面质量同时包括视觉、结构、可操作性、信息表达和状态完整性。

这份说明依据固定版本技能正文归纳。适用性判断不等于跨平台兼容性测试，也不代表执行后的效果已经实测。

## 核心覆盖什么

| 方向 | 典型问题 | 相关技能 |
| --- | --- | --- |
| 视觉细节 | 字体不协调、图标偏移、阴影或动画生硬 | better-ui、better-typography |
| 色彩系统 | 颜色用途混乱、明暗主题不清晰、前背景组合失败 | better-colors |
| 布局适应 | 窄屏遮挡、长内容溢出、翻译后结构失效 | better-layout、better-typography |
| 可操作性 | 键盘无法完成任务、焦点丢失、状态无法感知 | better-accessibility |
| 信息表达 | 按钮含义模糊、错误没有下一步、空状态不明 | better-writing |
| 整体审查 | 需要按影响排序的跨领域问题清单 | better-interface |
| 变更审查 | 想知道这次修改是否引入界面退化 | interface-review |
| 场景观察 | 想看真实组件在边界数据和窄容器中是否破损 | break |
| 方案探索 | 想比较同一个部件的不同设计方向 | variant |
| 参考解析 | 想理解某网页或效果的实现机制 | explain-interface |

## 能参与，但需要条件

- **新界面建设：** 领域规则可指导从零实现，仍需明确用途、内容、状态、技术栈与设计约束。
- **源代码修复：** 需要用户请求实现或修复、可写项目和对应工具；审查报告本身不证明代码已修改。
- **视觉判断：** 需要渲染结果。仅读源码可以提出代码层面的发现，不能宣称已观察到运行表现。
- **对比度测量：** 需要实际前背景与计算工具，不能目测一个数值。
- **原生界面：** 分组、清晰文案等原则可以借鉴；HTML、CSS、DOM 和浏览器配方需要平台适配，原生行为另行验证。

## 哪些工作要用其他流程补齐

产品定位、用户访谈、需求优先级、业务规则、后台接口、数据库、认证、全面安全与性能测试、发布运维、完整品牌资产生产及商业效果验证，都不属于该库的主要交付职责。

运行技能的模型可能具备这些其他能力，但“宿主模型能做”不等于“本库专门提供了这项工作流程”。界面局部动效性能建议也不等于整个系统的性能工程。

## 八类任务如何选入口

| 手头任务 | 建议入口 | 直接结果 | 关键边界 |
| --- | --- | --- | --- |
| 已有页面想优化 | better-interface | 跨领域报告；明确修复后再修改 | 只对实际检查范围作结论 |
| 分支或 PR 检查退化 | interface-review | 新增、退化与历史问题分类 | 默认只读，需可解析的 Git 基线 |
| 从零设计一个组件或页面 | 按需组合六个领域技能 | 指导界面实现；必要时另用 variant 比较部件 | 没有整站需求到后台部署的一键流程 |
| 现有组件验证边界内容 | break | 临时场景页与已观察破损 | 不等于持续回归或性能压测 |
| 比较部件设计方案 | variant | 默认三个可切换候选和取舍 | 用户选择后收敛，不证明转化率最优 |
| 理解网页或截图 | explain-interface | 机制解释与证据等级 | 截图无法还原原作者源码 |
| 只有想法，想交付完整产品 | 先进行需求与工程工作 | 页面任务明确后接入本库 | 本库只负责其中的界面质量环节 |
| 原生 iOS、Android 或桌面 | 平台开发流程 + 适配后的设计规则 | 可复用原则，平台实现另行处理 | 不能直接套用全部 Web 配方 |

## 避免几种误读

1. **11 个 skill 与 113 条能力不同。** 113 条是本研究细化整理的条目，不是 113 个独立技能，也不是 113 个实测结果。
2. **审查结果与实际修复不同。** 报告里的 Before / After 可以描述现状和建议，并不表示已经修改代码。
3. **完整 UX 与界面可用性不同。** 本库触及用户能否完成界面操作；需求洞察、用户访谈和产品策略需要其他研究方法。
4. **技能集与组件库不同。** 组件库提供可引用组件，模板提供初始页面；本库主要提供规则和参考配方。
5. **安装与执行不同。** 宿主需要实际加载技能、理解明确任务并调用工具；部分技能要求用户主动调用。
6. **优化旧页面与参与新页面都可以。** 核心规则可用于现有界面修复，也能指导新实现；完整产品的跨阶段交付仍需其他流程。
