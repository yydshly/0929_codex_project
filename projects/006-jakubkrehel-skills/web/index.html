READ THIS FIRST / 能力摘要

让 AI 有章可循地改善界面。

先看能做什么、留下什么成果，
再决定什么时候把它放进自己的工作。

这个库的能力是什么？

它是一组面向 Web 页面与组件的界面设计、优化和验证技能。把设计经验写成 AI 可读取的规则、操作步骤和验收要求，覆盖视觉、排版、颜色、布局、文案与可操作性，也组织审查、边界观察、方案比较和参考解析。

可实现什么效果？

让复杂内容更容易阅读，长文本与小屏布局更稳定，状态和错误更好理解，键盘操作更顺畅，视觉与主题更一致。它既能指导新界面的实现，也能帮助打磨已有页面。

根据任务得到不同成果

发现问题 → 有优先级的报告
要求实施 → 对应代码与样式改动
探索与学习 → 场景页、候选方案、机制解释

能力成立的条件

技能主要由说明和参考文档组成，实际读代码、修改和浏览器观察由宿主 AI 及工具完成。提供项目、真实内容、约束和明确交付要求后，再验证结果；完整产品仍需要需求研究、后台、数据、安全与部署等配套工作。

以下为固定版本文档归纳的预期效果。我们验证了本研究网页，尚未安装和运行上游全部技能。

6 个专业领域

指导怎样设计与实现

围绕页面质量的六个维度提供规则，可用于新实现、改进或专项检查。

  • 视觉与动效better-ui

    统一圆角、阴影、对齐和状态反馈，让页面细节协调、操作反馈连贯。

  • 文字排版better-typography

    调整字体、层级、换行与数字显示，让长内容可读、数据更新更稳定。

  • 颜色系统better-colors

    梳理色阶、语义变量、主题和实际对比度，得到更一致的配色及测量依据。

  • 操作与无障碍better-accessibility

    检查语义、键盘、焦点与表单反馈，让不同操作方式能完成同一任务。

  • 布局与适配better-layout

    处理分组、间距、窄屏、长内容及多语言，保持关键内容和操作可达。

  • 产品文案better-writing

    改进标签、提示、错误恢复和空状态，让用户知道发生了什么、下一步做什么。

2 个审查流程

确定问题、影响和优先级

把各专业领域的判断组织成报告。审查与实际修复是不同交付。

  • 整体界面审查better-interface

    按任务与页面范围协调六个领域，合并根因，交付有优先级的问题及验证记录；要求修复后再改代码。

  • 代码变更审查interface-review

    审查分支、PR 或未提交改动，追踪受影响界面，区分新增、退化和历史问题；默认只读。

3 个探索流程

观察边界、比较方案、理解实现

把抽象讨论转为场景、可运行候选和实现解释。

  • 极端内容观察break

    用真实组件展示空数据、长文本、多条目和窄容器，交付临时场景页与已观察的破损标注。

  • 部件设计候选variant

    围绕一个主要维度制作可切换方案，默认三版，比较取舍；选择后再落地并清理临时方案。

  • 参考网页解析explain-interface

    分析布局、图层、CSS 与动画，交付机制说明和可迁移配方，明确实测与推断。

数量口径：6 + 2 + 3 = 11 个技能；后两类合称 5 个工作流程。113 条是研究细化条目。interface-review、break、variant、explain-interface 要求主动调用；实际入口语法随宿主而异。

你的起步方式：一次只解决一个明确问题。

  1. 先拿一个现有研究页，用 better-interface 获取问题与优先级。
  2. 针对最影响阅读或操作的问题，明确要求实施修复，再验证桌面、手机和相关状态。
  3. 需要比较部件时用 variant；接入真实内容时用 break；改动完成后用 interface-review。

价值在于把“帮我美化一下”变成有范围、有成果、有验证的任务。无需每次调用全部技能；纯资料检索、后端逻辑或部署任务，优先使用对应工具与流程。

先建立整体认识 / POSITION & SCOPE

核心是界面质量，范围延伸到可用性。

一套围绕产品界面定制的 AI 工作规范。
11 个 skill 共同协作，也可以按需使用。

一句话定位

面向 Web 产品界面的
设计、优化、审查与探索技能集。

它把设计经验写成规则、操作步骤和验收要求，指导 AI 助手处理页面与组件。重点是用户能否看清、看懂、操作顺畅，以及真实内容到来后界面是否仍然稳定。

核心覆盖

直接处理界面问题

  • 视觉：字体、颜色、图标、表面层次、动画。
  • 结构：分组、响应式布局、长文本与内容增长。
  • 可用性：键盘、焦点、状态提示与辅助技术。
  • 表达：按钮、错误、空状态与术语。
  • 流程：审查改动、观察边界、比较方案、解释参考。

例如：让弹窗可用键盘关闭，让长名称不撑破卡片。

需要上下文与工具

能参与，但有前提

  • 新界面建设：需要用途、内容、状态与技术栈。
  • 代码修复：需要明确要求修改及可编辑项目。
  • 视觉结论：需要渲染页面与可用浏览器。
  • 颜色测量：需要真实前背景和计算工具。
  • 原生端应用：需要平台规范与实现适配。

例如：可以指导写一个卡片，但真正的代码执行由宿主完成。

不属于主要职责

需要其他工作流程补齐

  • 产品定义：市场定位、用户访谈、需求优先级。
  • 业务与后台：业务规则、接口、数据库、认证。
  • 整体工程：全面安全、性能、测试与发布运维。
  • 品牌资产：完整品牌策略、素材生产与版权处理。
  • 效果证明：转化率实验、用户研究和完整合规审计。

模型可能具备其他能力，但不能把它们算作这个库的交付范围。

“UI”包含什么？这里的 UI 涵盖视觉与界面交互质量，并触及可用性；完整 UX 研究仍需访谈、任务分析和真实用户验证。

只有已有页面才能用吗？已有界面的优化与检查是直接用途。新页面也可用领域规则指导，variant 可探索单个部件，完整产品开发还需要其他流程。

“定制技能”改了什么？定制的是 AI 的任务方法、判断依据和交付要求。仓库提供文档与参考配方；模型、编辑器和浏览器提供执行能力。

05 / HOW IT WORKS

设计知识，如何变成行动？

核心是可执行的工作规范。
模型解释规则，宿主提供代码与浏览器工具。

  1. 01

    识别任务

    从问题进入对应技能

  2. 02

    读取规则

    技能正文与参考配方

  3. 03

    理解项目

    组件、变量、现有规范

  4. 04

    执行与观察

    读代码、操作或修改

  5. 05

    交付与验证

    结果、证据、未验证项

知识层：各自负责

布局管空间，排版管文字显示，文案管措辞。跨领域问题按根因归属，避免重复报告。

流程层：组织判断

限定范围、分类问题、排序和汇总。先解决阻断任务的问题，再处理视觉细节。

工具层：提供证据

源码可检查规则；浏览器确认真实呈现。没有执行的检查，必须标记为未验证。

理解它的边界

这些技能以文档为主，不自带独立检测引擎。安装不会改变模型参数，也不自动保证界面质量、合规或转化提升。实际效果依赖模型能力、项目条件与验证。

interface-review、break、variant、explain-interface 在上游配置中要求用户主动调用。

06 / WHAT COMES NEXT

让规则更贴近自己的项目。

以下是研究提出的扩展方向，
不代表仓库已经实现这些功能。

01

团队设计规则

给领域技能增加团队颜色、组件、字号、密度与术语约定，并说明例外

预期价值与验证

价值：改法更符合自己的产品

验证：先用现有页面试审，检查是否误报有意设计

02

可计算检查

增加颜色计算、无障碍扫描、溢出探测等工具接口

预期价值与验证

价值：把部分文字规则落实为可重复结果

验证：记录工具版本、输入和输出，人工核对误报

03

持续组件回归

把 break 中有价值的场景转为长期样例与自动化用例

预期价值与验证

价值：后续修改时能复现已知边界问题

验证：需要维护测试数据、截图基线和环境

04

中文与多语言

增补 CJK 字体回退、标点、混排、翻译膨胀和语言专属例外

预期价值与验证

价值：提升非英文界面的适用性

验证：使用真实语言样例及目标设备验证

05

专业组件

增加表格、图表、权限、复杂筛选与表单规则

预期价值与验证

价值：扩展到高密度业务产品

验证：规定清晰责任领域，避免复制已有通用规则

06

评估样例库

建立已知错误、正确实现和等效重构样例

预期价值与验证

价值：测量漏报、误报和修复成功率

验证：按版本重复运行，记录人工判定依据

07

PR 流程集成

在变更流程接入界面审查并保存报告与渲染证据

预期价值与验证

价值：团队每次交付都能查看可追溯结果

验证：需要隔离预览、适当权限、耗时预算与结果存储

08

结构化报告

增加 JSON 输出字段、稳定问题标识和来源位置

预期价值与验证

价值：便于搜索、统计与跟踪同一根因

验证：校验格式，仍需对结论真实性做抽查

建议顺序 团队规则→可测量的工具→回归与评估样例
