# QM 研究记录

## 目标与范围

主项目为 yc-software/qm；Pi 是关联的执行基础对照。创建独立编号 012 的研究展示，不把原有 010 Pi 研究当作本次主成果。

回答能力与可交付功能、底层原理、组成模块、使用场景、个人意义五个问题，并通过实际源码验证 QM 与 Pi 的关系。

## 已核查的证据

1. README 与 getting-started：多人工作环境、作用域资源、部署前提。
2. orchestrator、harness-router、pi-harness、index：共同核心、引擎选择、Pi 实际导入、服务组装。
3. memory-providers：内置笔记与按空间选择外部提供方；捕获策略不等于训练权重。
4. skill-registry：固定版本导入、适用范围筛选与管理员治理，不能说所有技能都可直接无条件导入。
5. sandbox-resources 与 files-publication：环境生命周期与发布文件生命周期不同。
6. swarms：工作会话、持久队列、独立空白电脑以及生产存储条件。
7. SECURITY：内部认证用户的组织边界、共享策略、管理员权限、实验性质与局限。

## 研究结论

QM 可理解为 Agent 工作平台，其研究重点是执行能力之上的空间、身份、资源和持续工作。Pi 是执行适配器之一，QM 并非仅仅封装 Pi 的界面。两者分处不同层次，比较适合解释分工，不宜简单排名。

十类能力、八组模块和五个场景是本研究的整理框架，不是上游包计数或成功案例数量。个人意义是基于用户已有的开源研究与展示工作流作出的建议。

## 验证与限制

已核验生成文件、16 份源码哈希、导航锚点、跨项目链接、能力筛选、空间/流程/场景切换以及桌面和窄屏显示。交互通过浏览器语义键盘激活后检查实际显示内容；移动端比较表在容器内横向滚动，整页无横向溢出。结果记录在 [verification.json](verification.json)，[网页截图](assets/browser-home.png)存放 assets/。关联 Pi 页的现有验证也已通过。

本次没有部署 QM、连接真实私人服务或调用真实模型。因此不验证业务正确率、成本、性能、生产隔离或运行恢复；页面交互仅为解释性演示。研究网站使用本仓库 GitHub Pages 发布。
