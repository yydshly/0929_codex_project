## 五个问题的直接答案

**能力是什么？** 提供可被 AI 读取的工程和协作流程：澄清目标、记录术语与决策、研究和原型验证、拆任务、实施、调试、审查、交接，以及教学和写作。执行依赖宿主模型及其现有工具。

**使用场景是什么？** 持续迭代的软件项目最适合；资料研究、知识沉淀、学习和写作也有对应技能。简单改字、一次性小任务通常只需局部采用。

**包含哪些技能？** 全仓库 38 个：正式工程 18、正式通用 7、实验 9、专项 4。正式 Claude 插件仅列入前 25 个；“在仓库里存在”不等于“默认安装后即可用”。

**可以实现什么效果？** 在所需工具与权限具备、模型正确执行的条件下，可以得到需求规格、任务文件、测试与代码、诊断证据、审查报告、交接文档、原型、课程与文章。降低返工、缩短时间属于预期收益，本研究没有测得具体提升比例。

**对你的意义是什么？** 你已经在按编号积累开源项目研究。优先可借用第一手来源研究、统一术语、明确完成标准和交接方法；制作 Web 演示或正式产品时，再增加拆分、测试和审查。

## 研究中最值得注意的细节

- 技能主要是指令、参考与模板，未提供独立运行全部流程的统一调度引擎。
- `grill-with-docs` 把提问与领域记录组合起来；规格和实施任务由不同技能负责。
- `wayfinder` 主要解决“还有哪些决定没想清楚”；`to-tickets` 解决“已明确方案怎样实施”。
- `implement` 要求先审查再提交，而 `code-review` 当前用基准到 HEAD 的差异。两者组合时必须核对未提交修改是否进入审查。
- README 对 TDD 的概述、实验目录对 `retro` 的标注，与具体技能正文有差异；详见研究报告。
- 本库强调人的决策参与。若你偏好少打断，需要按既有授权、任务复杂度和验收条件调整，而非把全部追问照搬。
