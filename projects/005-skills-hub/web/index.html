先理解它是什么

Skills Hub管理 Skill 的工具：接入、增删改查与分发。

把多个外部 Skill 汇总到一个本地管理中心。你可以直接用桌面界面，也可以让 AI 通过附带的管理 Skill 帮你操作。

01 / 一图看懂

外部技能收进来，统一管理，再交给 AI 工具使用。

它本身是什么？

一个管理 Skill 的桌面工具。它把来自不同地方的技能收进同一个管理界面，再分发给选定的工具或项目。

它里面也有 Skill 吗？

有配套的 manage-skills-hub。这个管理 Skill 教 AI 操作 Skills Hub；写作、PPT、代码审查等业务技能通常从外部按需接入。

“统一管理”意味着什么？

默认是你电脑上的管理中心，可选跨设备同步。多个技能仍各自独立，不会因为放在一起就自动组成工作流。

依据：上游功能与 AI 管理说明 · CLI 管理命令

02 / 增删改查

把“管理”拆成四件具体的事。

示例中的业务 Skill 需自行接入。

增

把技能收进来

从 Git 仓库、本地目录添加，或导入已有技能。

例如：导入你挑选的代码审查 Skill。
删

移除不需要的技能

删除技能；不想删除时，也可以只停用。两者含义不同。

例如：删除重复技能，暂时停用实验技能。
改

调整配置和更新内容

修改标签、目标工具、范围和启用状态；从原始来源更新。

例如：把“全局使用”改为某个项目使用。
查

查找并阅读技能

搜索、筛选，查看技能说明、来源、文件与状态。

例如：查看某个技能做什么、来自哪里。

“改”的边界：这里主要指管理配置和来源更新，不能理解为已提供完整的 Skill 正文编辑器。要改变技能做事的方法，应在它的源文件中维护内容，再通过更新流程同步。

03 / 如何使用

先接入一个技能，走通一次完整流程。

依据固定版本文档整理，未实际安装。

  1. 1

    安装并打开 Skills Hub

    从项目官方发布页面选择适合系统的桌面安装包。这里打开的是研究网页，管理操作需要在 Skills Hub 应用中进行。

    查看官方发布页面
  2. 2

    选择一个实际需要的外部 Skill

    从已研究的库中挑选一个具体技能目录，使用 Git 地址或本地文件夹添加；也可以在 Explore 中查找。一个仓库包含多个技能时，先确认要安装哪一个。

  3. 3

    确定交给谁用、在哪里用

    设置标签，选择目标 AI 工具，以及全局或指定项目范围。首次尝试建议只选择一个工具、一个试验项目。

  4. 4

    到目标 AI 工具中验证

    确认它能发现技能，再做一次小任务。例如导入审查技能后，让 AI 审查一段测试代码；查看是否按技能要求输出。文件同步成功与任务效果是两项不同检查。

  5. 5

    持续整理与更新

    在 My Skills 中查看内容、改标签、启停或删除。有效的技能再扩展到其他工具和项目；需要双机使用时，再配置 Device Sync。

可选 · 通过对话管理

让 AI 读懂管理 Skill，再帮你操作。

在 Skills Hub 的 Settings → AI Management 中启用，安装配套 CLI 和官方管理 Skill，并按提示刷新终端环境。在 My Skills 中找到 manage-skills-hub，确认它已分发给你使用的 AI 工具。

示例请求：“列出我已安装的技能及其来源，帮我找出需要整理的项。”

这是用法示例，尚未执行。AI 是否能调用命令仍取决于当前工具环境和权限。单独安装 CLI 不会自动安装这个管理 Skill。

依据：Workflow 与 AI Management

04 / 对你的意义

把“研究过的技能”，变成“真正用起来的技能库”。

你正在积累开源项目研究和展示网页。研究集帮助你判断“有什么、值不值得用”；Skills Hub 可以承接挑选后的安装、分发和维护。这是基于你当前工作的采用建议。

现在 · 理解与筛选

你的研究集

记录能力、场景、来源和边界，挑出有用的具体 Skill。

下一步 · 纳入管理

Skills Hub

集中安装、分类、指定工具与项目、跟踪来源更新。

最终 · 用任务验证

你使用的 AI 工具

让技能参与网页、文档或代码任务，把效果再写回研究记录。

少做重复配置

同一个技能不必在多个工具中分别找来源、复制文件、追踪更新。

知道自己实际在用什么

研究过、装过、启用了、验证有效，是四种不同状态。管理工具帮助你掌握中间两种，效果仍需自己验证。

逐步形成个人工作方法

只保留经过实际任务验证的技能，为网页研究、文档整理等工作建立稳定的可用集合。

建议你先做的小试验：从现有研究中选 1 个技能，导入后只分发给 1 个 AI 工具的 1 个试验项目，完成 1 次实际任务，再决定是否扩大使用。如果仍处于浏览研究阶段，暂时无需安装全部技能。

05 / SCENARIOS

放到真实工作中理解

以下场景为基于已知能力的应用分析。

01 / 个人开发者

多个 AI 工具来回切换

同一套代码审查方法，在不同工具中反复安装。

安装一次 → 选择目标工具 → 统一更新

价值：减少重复维护，让方法文件保持一致。

适用条件

各工具对技能的理解与执行效果仍需分别验证。

相关能力 C01C05C09
02 / 多项目维护者

不同项目有不同规范

通用规范和项目专用要求混在一起，不易维护。

通用技能设为全局 → 专用技能分配给指定项目

价值：每个项目获得适合自己的技能集合。

适用条件

需确认目标工具支持项目目录；不提供运行时权限隔离。

相关能力 C06C08
03 / 多设备用户

换电脑或双机办公

新电脑缺少常用技能，旧电脑内容已发生变化。

连接同步仓库 → 同步内容 → 在新电脑配置工具目标

价值：复用技能内容，减少重新整理的工作。

适用条件

路径、工具目标和凭据需要按设备配置。

相关能力 C12C13
04 / 重度技能使用者

整理逐渐膨胀的技能库

来源不清楚、用途重叠、停用和清理成本高。

扫描导入 → 阅读内容 → 添加标签 → 批量启停

价值：形成容易查找、取舍和维护的清单。

适用条件

是否高质量、是否重复，仍需要内容判断。

相关能力 C03C04C08C11
05 / 小型开发团队

团队分发共同工作方法

新人需要反复获取评审、测试和文档规范。

维护共享 Git 来源 → 成员安装 → 分发给各自工具

价值：用同一来源传播可复用的工作方法。

适用条件

这是建议的用法；企业审批、成员权限和审计需另行建设。

相关能力 C01C05C09
06 / 习惯使用 AI 助手的用户

在对话中维护技能

安装、整理和检查技能时，经常切换窗口。

启用 AI 管理 → 加载管理 Skill → 由 AI 调用 CLI

价值：用对话完成受支持的技能管理操作。

适用条件

对话由宿主 AI 提供；Skills Hub 本身不承担通用 AI 推理。

相关能力 C14C04
06 / ARCHITECTURE

从一份技能，到多个工具

核心机制：文件 + SQLite + 目录适配 + 同步策略。

技能内容经过哪些环节？

一个 Skill 通常包含 SKILL.md，以及脚本、模板或参考资料。Hub 管理这些内容，下游 AI 工具负责读取并执行任务。

01 / 获取

Git · 本地 · 搜索

选择技能目录
读取名称与描述

02 / 归集

中心技能库

默认 ~/.skillshub
SQLite 记录来源与目标

03 / 分发

链接或复制

适配工具目录
选择全局或项目范围

04 / 使用

目标 AI 工具

发现并读取技能
按宿主能力执行任务

桌面：React + TypeScript + Tauri　｜　核心：Rust　｜　管理数据：SQLite　｜　设备间：Git 仓库

内容和配置分开存

文件系统保存技能正文和资源；SQLite 记录来源、版本、路径、目标、标签和状态。中心目录是一份内容库，不必等同于一个 Git 工作区。

依据：SkillStore 数据模型

链接优先，必要时复制

自动模式先尝试符号链接，Windows 可尝试 junction，失败再回退到复制。固定版本对 Cursor 采用复制策略。链接共享文件，副本需要重新同步。

依据：同步引擎 · 兼容说明

更新来源 ≠ 同步设备

来源更新把上游新内容带入中心库；设备同步交换各电脑上的可移植内容。同步清单保留描述、标签与文件哈希，剥离本地来源路径；合并比较基线、本地和远端。

依据：同步清单 · 合并计划

AI 管理通过命令行落地

宿主 AI 阅读管理 Skill，再调用 skillshub-cli。命令行支持 JSON 输出；它提供管理入口，通用对话与推理由宿主 AI 承担。

依据：CLI 命令定义
采用边界

什么时候值得采用

区分管理能力、执行能力与企业治理。

你需要的结果当前能提供仍需额外完成
多个工具共享技能目录分发、来源记录与更新逐个工具验证触发与执行效果
项目专用工作方法项目目标和启用状态配置检查技能依赖、权限与规范冲突
多电脑内容一致Git 同步、历史和冲突处理配置每台设备的路径、目标与凭据
团队统一技能版本共享来源和已有管理机制补充版本策略、发布审批和审计

采用判断：工具、技能、项目或设备越多，集中管理越有价值。只有一个工具和少量稳定技能时，手动管理也可能足够。同步成功不能替代任务效果验证。

07 / OPPORTUNITIES

从个人整理，走向可靠协作

分析建议 · 非已实现功能或官方路线图

01

版本锁定与可复现安装

已记录来源版本，具备更新和设备同步历史。

扩展入口：installer.rs · skill_store.rs
建议增加

增加项目锁定文件、固定提交安装策略、升级差异和受控回滚。

价值：让团队明确每个项目使用哪一套技能版本。
02

兼容性检查与效果评估

已有目录适配、状态检查和 CLI doctor 入口。

扩展入口：tool_adapters · CLI · 独立评估模块
建议增加

声明系统、软件和工具依赖；用固定任务评估触发、输出与失败率。

价值：把文件安装成功与任务执行成功分别衡量。
03

团队发布与治理

支持 Git 来源和跨设备内容同步。

扩展入口：内容发布服务 · 身份权限层
建议增加

增加团队技能目录、发布审批、角色权限、签名与操作审计。

价值：从个人管理扩展到团队可控的内容分发。
04

可复用的技能组合包

已有标签、批量操作和项目目标。

扩展入口：skill_store.rs · 安装流程
建议增加

将一组技能及版本组成前端包、入职包或发布检查包。

价值：减少逐个挑选和配置，支持项目模板化初始化。
05

面向外部系统的自动化接口

已有 CLI、JSON 输出和对话式管理。

扩展入口：cli/args.rs · cli/handlers.rs
建议增加

在既有命令能力上完善 CI 接入、稳定协议或 MCP 服务。

价值：让项目初始化与技能维护进入已有自动化流程。
06

基于真实使用的反馈

管理信息可描述安装和同步状态。

扩展入口：宿主工具集成 · 评估数据模型
建议增加

在用户授权下采集触发、耗时、失败及人工评价，按技能版本比较。

价值：帮助用户决定保留、改进或淘汰哪些技能。

建议优先顺序：版本与可复现性 → 兼容性和效果评估 → 团队治理。CLI 已经存在，进一步扩展应建立在现有能力上。
