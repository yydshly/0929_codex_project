# Skills Hub · 使用场景

以下为基于已知功能的应用分析，不代表实测效果。

## 多个 AI 工具来回切换

- 面向：个人开发者
- 问题：同一套代码审查方法，在不同工具中反复安装。
- 流程：安装一次 → 选择目标工具 → 统一更新
- 预期价值：减少重复维护，让方法文件保持一致。
- 边界：各工具对技能的理解与执行效果仍需分别验证。
- 对应能力：C01、C05、C09（见 [能力清单](CAPABILITIES.md)）

## 不同项目有不同规范

- 面向：多项目维护者
- 问题：通用规范和项目专用要求混在一起，不易维护。
- 流程：通用技能设为全局 → 专用技能分配给指定项目
- 预期价值：每个项目获得适合自己的技能集合。
- 边界：需确认目标工具支持项目目录；不提供运行时权限隔离。
- 对应能力：C06、C08（见 [能力清单](CAPABILITIES.md)）

## 换电脑或双机办公

- 面向：多设备用户
- 问题：新电脑缺少常用技能，旧电脑内容已发生变化。
- 流程：连接同步仓库 → 同步内容 → 在新电脑配置工具目标
- 预期价值：复用技能内容，减少重新整理的工作。
- 边界：路径、工具目标和凭据需要按设备配置。
- 对应能力：C12、C13（见 [能力清单](CAPABILITIES.md)）

## 整理逐渐膨胀的技能库

- 面向：重度技能使用者
- 问题：来源不清楚、用途重叠、停用和清理成本高。
- 流程：扫描导入 → 阅读内容 → 添加标签 → 批量启停
- 预期价值：形成容易查找、取舍和维护的清单。
- 边界：是否高质量、是否重复，仍需要内容判断。
- 对应能力：C03、C04、C08、C11（见 [能力清单](CAPABILITIES.md)）

## 团队分发共同工作方法

- 面向：小型开发团队
- 问题：新人需要反复获取评审、测试和文档规范。
- 流程：维护共享 Git 来源 → 成员安装 → 分发给各自工具
- 预期价值：用同一来源传播可复用的工作方法。
- 边界：这是建议的用法；企业审批、成员权限和审计需另行建设。
- 对应能力：C01、C05、C09（见 [能力清单](CAPABILITIES.md)）

## 在对话中维护技能

- 面向：习惯使用 AI 助手的用户
- 问题：安装、整理和检查技能时，经常切换窗口。
- 流程：启用 AI 管理 → 加载管理 Skill → 由 AI 调用 CLI
- 预期价值：用对话完成受支持的技能管理操作。
- 边界：对话由宿主 AI 提供；Skills Hub 本身不承担通用 AI 推理。
- 对应能力：C14、C04（见 [能力清单](CAPABILITIES.md)）
