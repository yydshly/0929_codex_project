## 设计与实现

### 1. 界面与本地核心

前端为 React、TypeScript 和 Vite，Tauri 提供桌面宿主；Rust 负责本地文件、Git、同步和存储逻辑。依赖清单包含 rusqlite、git2、reqwest 和 Windows junction 等。CLI 使用 clap 定义命令，支持 JSON 输出。

### 2. 内容与状态分离

中心目录默认 `~/.skillshub`，保存技能正文和资源。SQLite 的 `skills`、`skill_targets`、标签及同步相关记录保存来源、源版本、路径、启用状态和运行结果。中心内容库与设备同步使用的 Git 工作区不能混为一谈。

### 3. 获取与安装

安装器处理本地来源和 Git 仓库，识别技能目录并解析元数据；GitHub 子路径获取可使用稀疏检出及 API 回退策略。在线检索实现请求 skills.sh API。读取来源和复制文件并不包含完整运行环境安装。

### 4. 目录适配与分发

适配器定义工具检测目录、全局技能目录和项目相对目录，并支持自定义目标。自动同步模式先尝试符号链接，Windows 可使用 junction，必要时回退到复制。README 说明 Cursor 固定复制。引擎含目标已存在、路径重叠与冲突保护等处理，但本研究不据此宣称完成安全审计。

链接模式下多个工具读取共同内容；复制模式下工具获得独立副本，需要后续同步更新。启用/停用作用于管理和分发状态，不能保证宿主即时刷新。

### 5. 来源更新与系统任务

来源更新从 Git 或本地源取得内容，再同步目标。系统调度模块包含平台相关任务注册逻辑，例如 Windows 任务计划与 macOS launchd。是否能在具体设备上按时运行仍取决于系统、网络和凭据。

### 6. 设备同步与冲突

可移植清单包含技能名称、描述、来源信息、标签、内容哈希和文件哈希，剥离本地来源路径。合并计划比较基线、本地、远端三份清单，区分新增、删除、独立修改和冲突，并对符合条件的文本尝试合并。真实冲突仍可能需要用户决策。

### 7. 对话式管理

CLI 已包含 skills 的 list/show/search/status/check/install/deploy/undeploy/update/adopt/tag/remove，以及 agents、doctor、version、setup 等入口。上游 README 说明通过管理 Skill 引导宿主 AI 使用该 CLI。设备同步、计划任务、账户授权和应用设置仍属于桌面功能。

## 验证过程与限制

1. 通过公开 GitHub API 获取 main 当时的完整提交号和时间。
2. 从固定提交下载 14 个文件，记录各文件 SHA-256；README 首次下载失败后补齐。
3. 核对版本、工具适配器、数据库模型、目录同步、设备清单与合并、CLI 定义。
4. 使用一份 `web/content.json` 生成 14 项能力、6 个场景、6 项建议的文档和网页，避免文档与展示使用不同内容。
5. 检查来源文件哈希、HTML 锚点、相对资源、生成结果一致性，以及 HTTP 访问；浏览器验收见 [VALIDATION.md](VALIDATION.md)。

上一轮网页搜索缓存曾返回 0.10.0 代码片段；本轮直接读取固定提交后确认源码版本标识为 0.11.0，后续结论以本地固定快照为准。版本字段不用于证明安装包已经发布。

## 采用与扩展结论

适合同时管理多个工具、项目、设备或较多技能的用户。仅一个工具、少量稳定技能时，额外管理界面带来的收益可能有限。它改善管理一致性，实际任务质量仍取决于技能内容、宿主 AI 和工具环境。

扩展应优先考虑版本可复现与升级控制，再补充兼容性和效果评估，最后发展团队治理。多设备同步、CLI 和基础诊断已经存在，不能当作“尚未实现”的空白功能重新提出。
