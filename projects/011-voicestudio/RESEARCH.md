## 研究问题与结论

1. **它能交付什么？** 将文稿、参考录音、视频或接口请求变成旁白、配音视频、转写文字、故事和有声书。八类能力的输入、输出、实现与限制在 README 和展示页逐项说明。
2. **底层如何实现？** Electron / React 提供工作区，FastAPI 提供服务与任务入口；TTS、ASR、翻译和人声分离模型分别完成生成、识别与转换。适配器、长文分块、时间处理、混音和文件导出将模型结果组织成任务。
3. **和 Voicebox 是否只是不同界面？** 两者有大量重叠能力，但默认模型、可选引擎、工作区和已完成的任务链不同。简单接口串接可以做原型；稳定的视频制作需要处理多人、时长、术语、资源与异常。
4. **是否有直接复用？** 固定提交的 `backend/services/chunked_tts.py` 明确注明改编自 Voicebox，并调整音频拼接及采样率处理。仅能据此确认这个模块的联系，不能把整个项目认定为相同实现。
5. **对当前研究工作的意义？** 将已有研究复用为可听内容、教程和多语言版本；通过音频产物与数字人、个人助手组合。六个个人场景、六个扩展方向均为建议，跨项目集成尚未执行。

## 处理资料冲突与边界

- 646 种语言是默认模型覆盖声明；识别、声音设计和各条任务链不能据此推断同等覆盖。
- 引擎目录条目表示可选接入路径，不代表安装应用后全部模型即可直接运行。
- Voicebox 的 Windows 自动粘贴在 README 路线图与听写文档中存在状态差异，本研究不以此作确定性平台优劣结论。
- VoiceStudio 的基准汇总页没有已验证数据行，本研究没有据此编造速度、显存或音质排名。
- 应用 AGPL-3.0 与默认 OmniVoice 权重 CC-BY-NC 分开记录；应用的商业许可不替代模型许可。需要用于业务时应继续核对实际采用的权重和组件。
- 视频配音的时间匹配不等于人物嘴部画面重建；与数字人系统组合仍要验证接口。
