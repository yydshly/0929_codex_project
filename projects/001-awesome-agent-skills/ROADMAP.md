# 扩展方向与建议路线

以下是本项目的建设建议，不是上游承诺的路线图，也不表示已经实现。

## 两类扩展对象

**扩展目录本身**：使候选技能更容易发现和比较。上游当前的贡献机制以链接收录为主。[贡献规范](https://github.com/VoltAgent/awesome-agent-skills/blob/main/CONTRIBUTING.md)

**基于技能建设应用**：把业务流程、工具和验证方法组合起来。需要宿主加载技能并执行工具，可参考标准客户端实现方式。[实现指南](https://agentskills.io/client-implementation/adding-skills-support)

| 方向 | 最小产物 | 价值 | 难点 | 建议顺序 |
| :--- | :--- | :--- | :--- | :--- |
| 业务任务分类 | 输入、产物、依赖候选表 | 降低选型时间 | 分类与维护 | 先做 |
| 实测评估 | 一个场景的对照任务集 | 判断实际收益 | 样例偏差 | 先做 |
| 企业私有技能 | 一个流程＋模板＋正反例 | 沉淀团队经验 | 更新与责任人 | 验证后做 |
| 版本与依赖管理 | 来源、提交号、环境记录 | 提高复现性 | 多层版本变化 | 随试点建立 |
| 业务系统接入 | 只读或测试环境连接 | 使用真实数据 | 认证、字段语义 | 按场景需要 |
| 多技能编排 | 有明确阶段产物的任务链 | 支持较长流程 | 状态、重试、验收 | 单技能稳定后 |
| 智能技能发现 | 少量候选及匹配理由 | 降低大目录选择负担 | 误匹配、过期链接 | 有检索需求后 |
| 技能管理平台 | 发布、评测、反馈、权限说明 | 支持多团队使用 | 治理投入与分发 | 规模扩大后 |

## 当前工作区的可复用方向

可以把“开源项目研究”本身整理成技能：接收仓库地址，核对版本和许可证，区分事实与推测，生成研究文档，检查引用和本地链接。这与本工作区固定编号、模板和索引规则相匹配。建议先积累几个案例，确认稳定步骤后再封装。本轮只创建研究子项目，尚未制作或安装这个技能。

## 评测方案

选择一个场景，准备 10—20 个有明确验收方法的任务，覆盖正常输入、缺失字段、边界值和工具失败。数量是试点建议，不用于宣称统计显著性。

比较“同一模型与工具、不启用候选技能”和“启用固定版本技能”两组。保持输入、资源、完成标准一致，每项可重复 3 次并记录波动；隔离会话，避免前次结果影响后次。

| 指标 | 记录方法 | 限制 |
| :--- | :--- | :--- |
| 成功率 | 通过独立验收数／总任务数 | 不能只靠 Agent 自评 |
| 人工返工 | 修正内容和耗时 | 包含查证与格式修复 |
| 总耗时 | 开始到可交付，含等待和返工 | 区分首次和重复执行 |
| 成本 | 模型、工具及维护投入 | 无数据时写未知 |
| 误触发 | 无关任务受干扰次数 | 需加入相邻任务 |
| 稳定性 | 同一任务多次结果差异 | 平均值可能掩盖严重失败 |

每次记录至少包括任务 ID、模型与宿主版本、技能提交号、工具版本、数据版本、产物位置、独立验收、耗时、返工及失败原因。

## 试点决策门槛

实验前明确可接受的错误与成本，避免事后选择有利指标：

1. 关键产物能独立检查；无法验收的任务先缩小范围。
2. 质量或总工作量有可重复改善，同时记录退化案例。
3. 依赖、版本和失败处理可复现，维护责任明确。
4. 满足上述条件后，再扩大任务或增加外部系统。

目前所有量化收益均未知。后续可在本目录继续补充实验记录，保留本轮研究结论和日期。
