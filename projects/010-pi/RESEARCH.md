## 核心发现

1. Pi 有可直接使用的终端助手，也有供开发者复用的模型适配、Agent 循环和集成接口。
2. “生成报告”“研究仓库”来自模型、Pi 工具、工作方法和具体环境的组合，不能把所有业务能力归为 Pi 内置。
3. 当前根 README 列出七个公开模块，包括 pi-durable；不等于仓库只有七个目录。
4. 官方运行原理仍说明 CLI 持久会话为 JSONL 树；pi-durable 的 SQLite 存储不能被误写成 CLI 的默认存储。
5. 工具定义包括 read、bash、powershell、edit、write、grep、find、ls；完整工具集合和默认启用集合不同，页面不把它们全部宣称为默认工具。
6. 对话恢复、分叉与上下文压缩不自动回滚文件；扩展使用宿主进程权限。
7. 对用户的增量价值是理解和复用执行基础，逐步把研究方法固化成技能和专用工具；未证明迁移后效果更好。
8. 新版本已经内置 MCP 服务接入，可通过全局或项目配置连接 stdio / streamable HTTP 服务；本次纠正旧研究中“MCP 必须依赖扩展”的描述，保留服务配置和授权条件。

## 验证边界

本次执行研究页构建和浏览器验证；不安装 Pi、不调用真实模型、不进行上游性能、成功率或成本测量。页面中的执行步骤和场景均为教学示意。详细本地验证记录见 `verification.json`。

## 本地运行

在总仓库执行：

```powershell
node projects/010-pi/web/build.mjs
node projects/010-pi/web/verify.mjs
python -m http.server 8810 --bind 127.0.0.1 --directory site
```

然后打开 `http://127.0.0.1:8810/010-pi/`。

后续如果实测上游，先限定一个小任务：读一个文件、修改一个函数、运行一个检查；记录所用模型、工具轨迹、预期结果和实际差异，再验证一个自定义 Skill 或工具。
