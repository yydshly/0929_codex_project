PI AGENT HARNESS / 能力与原理研究

让模型的判断，
成为实际行动。

Pi 是可扩展的 Agent 执行基础，也自带终端助手。它把模型判断连接到文件、命令和真实工具，让一个目标经过多轮操作形成可检查的成果。

01内置基础

读懂代码和资料

读取文件，结合模型分析内容；通过命令或可选搜索工具定位依据。

可以交付代码解释、研究笔记、问题位置与证据。
需要什么 · 能力边界

输入：项目目录、文件和问题

条件：网页检索和内部数据访问需要另配工具或可用命令。

02内置基础

修改代码与文档

调用读写与编辑工具，把模型提出的改动落实到文件。

可以交付代码修改、Markdown 文档、配置文件。
需要什么 · 能力边界

输入：修改目标、约束和待编辑文件

条件：写入成功不能证明业务逻辑正确，仍须检查。

依据：工具定义 ↗
03内置基础

运行命令并验证

运行命令，把输出或报错交回模型，支持继续修正。

可以交付测试输出、构建结果、数据处理文件。
需要什么 · 能力边界

输入：测试命令、项目依赖和执行环境

条件：运行权限来自启动 Pi 的进程；依赖需准备。

依据：工具定义 ↗
04内置基础

持续完成多步骤任务

多轮进行模型判断、工具执行、结果反馈，并接收中途指导。

可以交付由多个操作形成的一次交付，以及可查看的执行记录。
需要什么 · 能力边界

输入：目标、上下文与验收标准

条件：没有预先保证成功的流程；模型和工具都可能出错。

依据：Agent 核心 ↗
05内置基础

恢复会话与探索分支

恢复历史、返回树节点、分叉或复制当前分支。

可以交付可继续的会话、不同方案的独立讨论路径。
需要什么 · 能力边界

输入：之前的任务记录或一个分支点

条件：对话分支不自动撤销文件修改；代码版本另用 Git 管理。

依据：会话与上下文 ↗
06内置基础

管理长任务上下文

组合当前分支和资源，按需加载技能，压缩较早的历史。

可以交付更集中、可继续使用的模型上下文。
需要什么 · 能力边界

输入：历史消息、项目说明与当前任务

条件：压缩是有损摘要；会话保存不等于永久准确记忆。

依据：运行原理 ↗

切换和接入模型

统一模型消息、流式输出及工具调用接口。

可以交付可在统一 Agent 工作流程中使用的模型能力。
需要什么 · 能力边界

输入：供应商配置、认证和可用模型

条件：模型仍由外部服务或已配置的本地端点提供。

08资源定制

复用自己的工作方法

用模板复用输入，用 Skills 按需加载方法，用主题调整终端外观。

可以交付可反复使用的研究、开发或写作流程。
需要什么 · 能力边界

输入：研究规范、写作要求或重复任务

条件：技能说明不能代替缺失的工具、账号或业务接口。

依据：快速开始与定制 ↗
09接入与扩展

接入外部与自定义工具

通过内置 MCP 接入服务工具；也可用扩展注册自定义工具、命令和事件。

可以交付知识库查询、检查器、业务操作等专用能力。
需要什么 · 能力边界

输入：MCP 服务配置，或业务 API、权限和工具实现

条件：现成 MCP 服务需配置和授权；没有对应服务时仍需开发。

依据：MCP 工具接入 ↗

做自己的 Agent 产品

用 SDK 嵌入进程，或用 RPC 控制 Pi 进程；JSON 模式输出结构化事件。

可以交付自建研究助手、任务服务或网页工作台的执行基础。
需要什么 · 能力边界

输入：产品界面、任务模型和业务规则

条件：登录、多用户隔离、后台调度和运营治理由宿主补齐。

02

再看原理：一个目标如何变成行动

模型负责选择下一步，Pi 负责组织上下文和执行，工具产生真实结果。一次任务通常需要多次模型请求。

人 / 宿主应用

给出目标

指定工作目录、任务要求和验收标准。

例如：修复价格计算错误，并运行已有测试。

交互教学示意 · 点击步骤查看职责，不调用模型或执行命令。结果需要继续处理时，流程回到模型判断。

会话是一棵树

当前分支形成下一轮历史。恢复、分叉和复制会话用于继续工作或比较方案；文件修改仍需 Git 等机制管理。

依据：会话与上下文 ↗

上下文按任务组合

项目说明、当前分支、工具和技能描述进入请求；技能正文按需读取，旧历史可压缩为摘要。

依据：运行原理 ↗

反馈推动下一轮

工具的输出和错误重新交给模型。参数校验、事件和队列帮助控制运行，但不替代质量验收。

依据：Agent 核心 ↗
03

包含哪些模块

按当前根 README 的七个公开模块归纳；不是把仓库中所有子目录当作七项独立产品。

01

pi-ai

模型接入层

把不同供应商的消息、工具调用与流式结果接到共同接口。

模型配置与请求 → 统一响应、事件和用量信息。

你需要换模型或接多个供应商时。

查看固定版本依据 ↗
02

pi-agent-core

Agent 执行层

维护消息和运行状态，组织模型请求、工具调用、反馈和事件。

任务与工具 → 多轮执行过程及最终回复。

你要构建有自定义工具的 Agent 时。

查看固定版本依据 ↗
03

pi-coding-agent

可直接使用的助手

装配工具、会话、资源和界面，提供终端、脚本、SDK 与 RPC 入口。

项目与目标 → 文件改动、命令结果、可恢复会话。

你直接用 Pi，或把现成会话能力嵌入产品时。

查看固定版本依据 ↗
04

pi-tui

终端呈现层

提供终端组件与差分渲染，显示输入、文本和运行状态。

界面状态 → 终端中的交互反馈。

你需要定制终端体验时。

查看固定版本依据 ↗
05

pi-durable

持久化运行基础

提供会话、任务和文档记录契约，以及内存、JSONL、SQLite 存储实现。

结构化记录 → 可保存、读取与恢复的状态。

你构建需要持久记录的应用时；不等于成品任务平台。

查看固定版本依据 ↗
06

chord

应用组成基础

组织服务、插件、RPC 与复制状态，支持组件之间的协作。

服务与状态定义 → 可组合的应用运行结构。

你做复杂宿主应用时；独立基础包，不是每次 CLI 任务的必经步骤。

查看固定版本依据 ↗
07

pi-telemetry

诊断与观测契约

定义供应商无关的诊断接口、类型化数据和参考适配方式。

运行诊断 → 可交给观测系统的结构化记录。

你需要接入日志与监控时；本身不是现成监控后台。

查看固定版本依据 ↗
阅读顺序：先看 pi-coding-agent → pi-agent-core → pi-ai，再按产品需求查看其余基础包。CLI 会话文档仍说明默认使用 JSONL；pi-durable 提供 SQLite，并不意味着 CLI 默认改用了 SQLite。
04

放进真实使用场景

从你要得到的成果出发，选择 Pi 的使用层次。场景是可构建方案，外部工具和业务规则需要准备。

任务输入

仓库资料、固定版本、研究模板和你关心的问题。

  1. 定位 README 与核心代码
  2. 整理能力、原理和来源
  3. 按模板生成研究文档
  4. 检查引用与遗漏
预期成果

中文研究报告、来源索引、待验证清单。

需要补齐：联网获取资料需可用命令或查询工具；网页制作需相应制作与验证工具。

对你的价值：把我们反复使用的研究方法沉淀为 Skill，减少每次重新解释格式和标准。

05

对你的意义：从研究工具到自己的产品

我们已经看过很多 Agent 工作台。Pi 的价值是帮助你理解并复用它们下面的执行基础。

现在 / 学懂执行

把原理对应到一次任务

以研究仓库或修复小错误为例，观察上下文、模型选择、工具输出和验证结果。你能更准确判断一个项目增加了什么。

下一步 / 固化方法

做自己的研究工具

将能力、原理、来源与验证标准整理成 Skill；再增加一个检查引用或查询资料的工具，形成可复用的研究流程。

以后 / 形成产品

构建专用 Agent 服务

通过 SDK 或 RPC 接入你的网页和业务流程，逐步补上权限、记录、评测与部署。是否采用它，应由真实任务表现决定。

与 Pi Web、oh-my-pi、QM 有什么关系？

Pi 提供执行基础；Pi Web 把 Pi 整合成网页工作台；oh-my-pi 基于 Pi 强化编程工具；QM 可以选用 Pi，再组织团队空间与资源。它们处在不同层次，并不互相等价。

关系依据：此前本地研究，以及 Pi Web、oh-my-pi、QM 主研究 项目说明。
